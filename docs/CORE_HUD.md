# Игровой HUD и редактор размещения

Реализовано 13–14.11.2026; последняя сверка 14.11. Windows Godot 4.7.2.
Общий компонент [game_hud.gd](../scripts/core/game_hud.gd) подключён
нативным Полигоном и CoreMovementLab, поэтому работает на обоих Полигонах,
обоих Прологах, Терре и Хабе. Это первая функциональная заглушка оформления,
не окончательно утверждённый художественный дизайн интерфейса.

## Требование и управление

Пользователь поручил чистый игровой экран, отдельное включение телеметрии
без F1, произвольное размещение HUD, точные игровые значения и сохранение
как прежних настроек разработчика. Существующие механики/личные профили
сохраняются. Новые иконки или картинки в билд не добавлялись: выбран вариант
показа названия оружия.

- Кнопка «Телеметрия» / **F12** показывает и скрывает диагностические данные.
  По умолчанию выключена, состояние входит в профиль. **F1 сохраняет только
  прежнее управление зонами/коллизиями и не меняет телеметрию.**
- Кнопка «Настроить HUD» / **H** включает редактор. Перетаскивать блоки
  мышью; выбрать блок в списке, изменить X/Y, размер и отдельную видимость.
  H/«Готово» закрывают редактор. Escape сначала завершает ввод числа,
  затем закрывает редактор. F2/F3/F4/F5/F6/F10 завершают редактирование HUD
  перед открытием соответствующего окна разработчика.
- **«Сохранить HUD»** записывает HUD в существующий профиль камеры.
  Закрытие редактора оставляет изменения в памяти, но само диск не пишет.
- **«Сбросить размещение»** возвращает только позиции/размеры. Не стирает
  общую видимость, индивидуальные выключатели, телеметрию и остальные настройки.
- В F2 → Игрок → Камера и визуал → **HUD** находятся те же параметры,
  кнопки перехода к перетаскиванию и сохранения. Общие Save/Load/Reset/JSON
  продолжают обслуживать прежние пять профилей. Нижние действия профиля
  камеры относятся ко всему этому профилю, а не только размещению.

Во время редактирования появляется системный курсор, блокируются игровые
движение/огонь/смена слотов. Мир не получает новую команду паузы; исходное
состояние паузы сохраняется. После клика в UI требуется отпускание кнопки
мыши перед новым выстрелом. Модальное файловое окно блокирует горячие
клавиши редактора. F12 не срабатывает при вводе текста/числа.

## Данные и размещение

| Блок | По умолчанию | Источник истинных значений |
|---|---|---|
| Здоровье | Слева внизу, над выносливостью | player.health / maximum_health(); реальная дробная величина, не оценка по попаданиям. |
| Выносливость | Слева внизу | 3D reserve / 2D sprint_reserve; доля, процент и оставшиеся секунды от текущего sprint_duration. При выключенном спринте явная подпись. |
| Оружие | Справа внизу, над боезапасом | Текущий weapon_id / equipped_weapon_id и имя из каталога; не выбор, оставшийся в меню. |
| Боеприпасы | Справа внизу | Текущий магазин / ёмкость, резерв и сумма магазин+резерв выбранного оружия. Разные калибры двух слотов не складываются в одно число. Есть признак reload. |
| Гранаты | Нижняя центральная область | Реальный grenade_controller.count в 2D и grenade_controller_3d.count в нативном 3D (с 14.11); подготовленная граната отдельно «+1 в руке». |
| Гаджеты | Центральная область над гранатами | Подготовленный слот. Подсистема инвентаря отсутствует, поэтому «Не подключены»; количества не выдумываются. Для будущего реального источника есть optional get_hud_gadgets на владельце сцены. |

Чтение идёт из действующих контроллеров каждый визуальный кадр, в том
числе при паузе/ручной правке HP. HUD не хранит независимые копии патронов,
не меняет урон/боезапас и не управляет механиками. HP/секунды выводятся
до трёх дробных знаков, доля выносливости — с десятыми процента; сама
игровая величина не округляется. read_data/last_data сохраняют исходные числа
для проверки. Название/боезапас сразу следуют настоящей смене 1/2.

Размещение нормализовано по свободному пространству: 0 — левый/верхний край,
1 — правый/нижний с учётом размеров блока. Поэтому после изменения разрешения
сохраняется относительное расположение, а целый блок остаётся в viewport.
Нет обязательной сетки/запрета размещения в центре. Размер каждого блока
0,5–2×, отдельная видимость, общий HUD-выключатель и непрозрачность 0,2–1.
На слишком маленьком viewport эффективный размер ограничивается его
границами без переписывания сохранённого масштаба. В редакторе видны
также скрытые блоки, чтобы их можно было снова включить/переместить.

Блоки рисуются в CanvasLayer 10: выше мира, ниже F2/карты/меню. Они не
перекрывают управление игрой мышью вне редактора; toolbar имеет собственную
защиту от стрельбы кликом. Нет зависимости от положения/зума Camera2D/Camera3D.

## Телеметрия

Технические старые строки состояния/скоростей/гравитации/стрельбы,
служебный заголовок выбранного оружия и подписи чисел/состояний противников
скрыты по умолчанию. FPS в игре дополнительно подчиняется F12, сохраняя
собственный существующий параметр показа FPS; в меню его прежнее поведение
сохраняется. Текст отчёта взрыва тоже относится к телеметрии, а геометрия
отладки F1 остаётся самостоятельной. Контекстные игровые подсказки дверей
и прежние графические индикаторы противников не подменяются диагностикой.

F2 → Тестирование → Телеметрия и F5 → HUD используют тот же флаг, что
кнопка/F12. Включение F1 не включает текст и не меняет сохранённый флаг.
Выключение телеметрии не скрывает шесть игровых блоков HUD.

## Профили и совместимость

Параметры/диапазоны: [hud_parameters.gd](../scripts/core/hud_parameters.gd).
Поля CoreCameraSettings имеют префикс hud_: 19 числовых параметров
(12 координат, шесть размеров, непрозрачность) и восемь переключателей
(общий HUD, телеметрия, шесть блоков). Файл прежний core_camera.cfg,
секция camera; в общем JSON это прежний раздел camera. Шестой файл
профиля/новый JSON-формат не создавались. Старые CFG/JSON без этих полей
получают заданное начальное размещение и выключенную телеметрию.

Специальное «Сохранить HUD» читает существующий camera CFG и меняет
**только HUD-ключи**, сохраняя остальные секции/ключи/размерную версию.
Если файла нет, он создаётся из текущего ресурса камеры. При ошибке чтения
существующий файл не перезаписывается. Эта кнопка не сохраняет посторонние
несохранённые изменения камеры и не трогает четыре других CFG.

Обычный F2 «Сохранить всё» и импорт сохраняют весь текущий набор как прежде.
Неверный тип нового HUD-поля отклоняет весь JSON до применения.
Никаких автозаписей личного профиля при запуске, каждом кадре или
перетаскивании. Пользователь явно нажимает сохранение/импорт.

## Проверки и границы

- Новый [game_hud_integration](../tests/game_hud_integration.gd): **144/144**
  в оконном прогоне. Шесть входов, реальные дробные HP/запас/магазин/названия,
  гранаты 2D, отсутствие выдуманных 3D-гранат/гаджетов, независимость F1/F12,
  живой редактор, размеры/видимость/перемещение, реальные GUI-события drag,
  настоящий переход на пистолет и обратно, сохранение/загрузка CFG/JSON,
  новый запуск, целый блок в границах, неверный HUD JSON без частичного
  применения, сохранность посторонних полей/других профилей. Включена проверка
  компактных размеров после обнаруженного роста autowrap-Label.
- Целевые регрессии: developer_routes_parity, developer_native_controls_smoke,
  developer_3d_integration, weapon_loadout_smoke, pistol_pause_cycle_3d,
  shooting_3d_input_smoke. Фактические итоги — журналы в папке ниже;
  все семь наборов вместе с game_hud_integration прошли итоговый запуск. Это не новый прогон всей базы из 52 наборов.
- Все записи/импорты проверяются в отдельных TEMP-профилях с изоляцией
  APPDATA/LOCALAPPDATA. Пять оригинальных CFG проверяются SHA256 до/после;
  их состояния не сбрасываются для тестов. Итоговая сверка: все пять SHA256 совпали.
- Оконные default/editor осмотрены. Это приёмка работоспособности заглушек,
  не окончательное утверждение их дизайна пользователем. Полный FPS-бенчмарк
  и новый Windows EXE не делались. Прежние открытые проблемы ADS/паркура/
  рэгдолла не объявляются исправленными этой задачей.
