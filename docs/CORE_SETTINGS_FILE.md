# Перенос всех настроек

В **режиме разработчика · F2**, над разделами настройки, есть две кнопки:

- **«Экспорт JSON»** сохраняет текущие настройки всех четырёх разделов в один JSON.
- **«Импорт JSON»** загружает их из выбранного JSON, обновляет интерфейс
  и сохраняет все четыре пользовательских профиля для следующих запусков.

В файловом окне можно выбрать папку и имя. Предлагаемое имя —
`dead-platform-settings.json`. Экспорт включает 134 параметра: обычное движение,
максимальное здоровье героя (1–1000 HP, по умолчанию 100),
спринт (скорость, шум шагов, ограничение времени и восстановление), множители дальности прыжка для обоих режимов,
склоны ходьбы/спринта и отдельные множители/углы дэша, разрешение дэша в воздухе, подкат (скорость,
разгон для старта, длительность, торможение, восстановление, высота, урон),
сбивание (переключатель, шанс, порог скорости, отдельное время на земле для людей и зомби, отбрасывание), приседание
(высота, скорость, шум шагов), стрельбу и её визуальные/звуковые эффекты, зональный урон,
прочность конечностей, режим огня, камеру
и переключатель ограничения по краям уровня, три параметра блюра героя и сглаживание тела, зрение со сдвигом X, слух,
патруль, ближний бой, ограничения/скорость ползания, сбрасывание игрока с зомби
и реакцию на попадания (включение, память источника урона, множитель скорости).
Каждая из семи вкладок зомби имеет сохраняемый переключатель механики.
Бессмертие героя и текущие HP — инструменты тестирования текущей сессии;
в балансировочный JSON они не входят. `movement.max_health` сохраняется,
а старые JSON без этого ключа получают 100 HP.
Старые JSON без новых ключей получают включённые значения; прежний
переключатель реакции на попадания сохраняет записанное значение.
Число, которое ещё
редактируется в панели, подтверждается перед открытием файлового окна.

На время выбора файла игра останавливается. Отмена, Esc и крестик закрывают
окно и возвращают прежнее состояние паузы. Клик по диалогу не становится
выстрелом после его закрытия. Положение героя, враги и статистика боя
не сбрасываются при переносе настроек.

Общие «Сохранить всё», «Загрузить всё», «Сбросить всё» работают со всеми
четырьмя профилями. Кнопки «Сохранить», «Загрузить», «Сброс» внизу страницы
работают с текущим разделом,
а кнопки файлового переноса всегда относятся ко всем настройкам. Экспорт
не меняет локальные сохранения. После успешного импорта используются
обычные `user://core_movement.cfg`, `user://core_shooting.cfg` и
`user://core_camera.cfg`, `user://core_zombie.cfg`; связь с импортированным JSON не сохраняется.
Чтобы обновить переносимый файл после дальнейших правок, экспортируйте его
ещё раз. Перед перезаписью существующего файла файловое окно запрашивает
подтверждение. Если часть локальных профилей не удалось сохранить,
настройки применяются в текущей игре и в панели появляется сообщение
о необходимости сохранения.

## Формат

Полный базовый пример: `docs/core/settings-defaults.json`.
Значения можно редактировать в текстовом редакторе. Структура:

```json
{
  "format": "dead-platform-settings",
  "version": 1,
  "movement": { "run_speed": 320.0, "uphill_multiplier": 0.7 },
  "shooting": { "rounds_per_minute": 1000.0, "fire_mode": 0 },
  "camera": { "zoom": 1.0, "limit_to_level": true },
  "zombie": { "detection_range": 360.0, "vision_angle": 120.0 }
}
```

`fire_mode`: 0 — автоматический, 1 — одиночный. `limit_to_level`
и `zombie.damage_reaction_enabled` — логические
`true` или `false`. Остальные значения — конечные числа в единицах,
показанных в панели настройки.

Обязательны маркер формата, версия 1 и разделы `movement`, `shooting`, `camera`.
Раздел `zombie` необязателен для совместимости со старыми файлами;
при его отсутствии берутся базовые параметры зомби. Если известный параметр
не указан, берётся базовое значение проекта; это позволяет читать старые
файлы после добавления новых настроек. Неизвестные ключи игнорируются.
Числа вне диапазона ограничиваются диапазонами регуляторов. Зависимые
значения нормализуются: короткий прыжок не сильнее полного, восстановление
дэша не короче его длительности, максимальный разброс не меньше начального,
дальность удержания цели зомби не меньше обнаружения, угол зрения не больше 180°.
При таком исправлении появляется сообщение.

Некорректный JSON, чужой формат, неподдерживаемая версия, пропущенный раздел,
неверный тип значения или файл больше 1 МБ отклоняются до применения.
Текущие настройки и локальные профили остаются прежними. JSON читается как
данные; импорт не загружает ресурсы и не выполняет команды из файла.

## Реализация и проверка

- `scripts/core/settings_file.gd`: запись и проверка данных, подготовка всех
  разделов до изменения активных ресурсов.
- `scripts/core/movement_lab.gd`: файловое окно, применение, сохранение
  профилей и восстановление состояния паузы.
- `scripts/core/settings_file_dialog.gd`: отмена по Esc внутри окна.
- `scripts/core/movement_overlay.gd`: кнопки переноса в каждом окне настройки.

`tests/settings_file_smoke.gd`: 67 проверок — полный перенос, подтверждение
ввода, все контролы, камера на паузе, сохранение между запусками, независимость
ресурсов проекта, отказ от неправильных файлов, диапазоны и зависимости,
отмена тремя способами и безопасные клики, старые файлы без зомби,
старые параметры зомби без слуха, сдвига X и настроек ползания, отклонение неверного раздела
зомби до применения остальных. Тест использует временную папку,
не меняя пользовательские профили.

```sh
/Applications/Godot.app/Contents/MacOS/Godot --headless --fixed-fps 60 --path . -s tests/settings_file_smoke.gd
```

Превью кнопок — `docs/core/settings_file_controls.png`; диалог —
`docs/core/settings_file_dialog.png`. Инструмент — `tools/capture_settings_file.gd`.
