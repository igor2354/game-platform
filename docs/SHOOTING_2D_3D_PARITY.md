# Аудит соответствия стрельбы 2D → 3D — 12.11.2026

Поручение: перенести все существующие механики стрельбы. Этот документ —
проверка исходного кода, не игровая/звуковая/художественная приёмка.
Перенос не завершён. Базовая работоспособность четырёх профилей не доказывает
сохранение поведения всей системы.

Источники: scripts/core/shooting.gd, shooting_settings.gd, projectile.gd,
projectile_tracer.gd, assault_muzzle_flash.gd, weapon_casing.gd, casing_pool.gd,
casing_audio.gd, muzzle_smoke.gd, surface_impact.gd, enemy_impact.gd,
aim_beam.gd; сравнение с shooting_3d.gd, shooting_3d_audio.gd,
shooting_3d_effects.gd, shooting_3d_reticle.gd и polygon_3d_combat.gd.

Статусы: «база» означает реализованную часть, а не полный паритет.

## Вывод

Текущий 3D-контроллер — новая частичная реализация. Он не является полным
портом CoreShootingController. Ошибка процесса: я добавлял видимые фрагменты,
не закрывая перечисленные контракты и проверки исходного контроллера.
Текущие smoke-тесты проверяют лишь ограниченные сценарии. Они не доказывают
эквивалентность 2D, фактическое прослушивание или художественное соответствие.

Для переноса использовать эту таблицу как обязательный список приёмки:
исправление → сравнительная проверка 2D/3D → запись фактического результата.
Статус меняется лишь после реализации и проверки, а не после объявления
намерения. Сама эта сверка не меняла игровое поведение и не повторяла тесты.
## Закрыт блок обработки спуска — 12.11.2026

Реализация: `shooting_3d.gd::tick_trigger`, вызов из физического тика
`polygon_3d_combat.gd`, после обновления оружия (physics priority 10).
Render-process больше не создаёт выстрелов. Короткий клик, попавший между
тиками, сохраняется через `_input`/queued_single_press и потребляется один раз.

Повторён порядок `shooting.gd::update_state` и `finish_tick`:
- cooldown сохраняет отрицательный остаток только при продолжающемся огне;
- после прекращения огня cooldown ограничен одним интервалом;
- AUTO использует удержание, SINGLE — новое нажатие или queued_single_press;
- смена режима при удержании требует отпустить кнопку;
- пустой магазин щёлкает один раз на новое нажатие, без повтора по таймеру;
- выключение оружия, запрет ввода и перезарядка подавляют огонь;
- выключение магазина сохраняет боезапас, не требует патронов и не щёлкает;
- начало/отмена перезарядки очищают ожидающее одиночное нажатие.

Проверки 12.11 в Windows Godot 4.7.2:
`shooting_3d_trigger_parity.gd`: 8100 сравнительных тиков с реальными
update_state/finish_tick исходного 2D-контроллера. Только создание пули
в эталоне заменено счётчиком; прицел/отдача исключены из этого теста.
Сравнивались shots, magazine, cooldown, dry_clicks и trigger_needs_release.
Шаги времени около 1/30, 1/60, 1/144 с с разбросом ±20%; RPM 180/480/1000;
удержание/отпускание, короткие клики, смена режима, блокировки, пустой
магазин и переключение weapon_enabled/magazine_enabled. Расхождений нет.
Это шаги симуляции, не измерение графического FPS.

`shooting_3d_input_smoke.gd`: реальный InputEventMouseButton в сцене
3D-Полигона, физика 60 Hz — 8 выстрелов STG за контрольный интервал,
один щелчок при длительном удержании пустого магазина и второй после
нового нажатия; failures=0. Проверки попаданий четырёх оружий и каталога
повторены, failures=0. Профили пользователя не загружались/не записывались.

Закрыты первые четыре пункта аудита поведения огня (темп, SINGLE,
смена режима, сухой щелчок). Это не приёмка остальных подсистем стрельбы.
## Отдача, движение и перезарядка — реализация 12.11.2026

`shooting_3d_recoil.gd` содержит исходные функции consume_manual_recoil,
_clamp_aim_recoil, _shift_shot_cursor, _tick_recoil и _apply_shot_recoil.
Отдельный модуль не создаёт 2D-физики. Геометрия прицела преобразуется
между экраном и плоскостью 3D; долги отдачи меняют базис при изменении
камеры. Ввод относительный, курсор захвачен в игре и освобождается для
окон настроек/паузы/меню. Возвращается только оставшийся долг. Скрытие
дополнительной стрелки учитывает hide_cursor_in_game.

В сцену подключены recoil_back, kick/shake камеры с исходной формулой,
возвратом и kill_camera_boost. Множители reload/ADS/hip-очереди берутся
из исходной формулы, применяются перед движением. Финальный выстрел —
после движения, чтобы вход в лестницу/дэш/подкат отменял его в том же тике.
Учтено движение задом относительно направления оружия. При ADS обычное
передвижение выбирает прежний цикл ходьбы. Физические параметры базового
передвижения/коллизии не изменены.

Перезарядка фиксирует duration/facing/start direction на входе; настройка
длительности посреди действия не меняет активный таймер. Отмена останавливает
звук, очищает queued press и не переносит патроны. Выключение оружия/магазина,
смерть, лестницы/паркур/дэш/подкат отменяют её. Изменение ёмкости сохраняет
общее количество патронов. Пустой магазин отделяется в фазе 0,42.
Руки следуют прежним фазам 0,17/0,42/0,52/0,70/0,80/0,90, включая движение
к подсумку и затвору; это 3D-адаптация поз, не доказательство тождественности
рисунку 2D. Движение затвора цельной STG не выделено: перемещается рука.

STG: магазин отделяется от рабочей Mesh в памяти по разметке треугольников;
материалы сохранены. Исходный GLB не менялся. Для остальных оружий магазин
экструдируется по исходному magazine_shape каталога: это блокинг до появления
их моделей. Пустые магазины — RigidBody3D, остаются на земле, удаляются F8.
Контакт пальцев/закрытие шва выделенной сетки не прошли художественную приёмку.

Проверки Windows Godot 4.7.2:
- shooting_3d_recoil_parity: 3000 тиков исходных и новых функций с одинаковым
  seed, hip/ADS, manual, auto during fire, continuous; состояния/курсор совпали.
- shooting_3d_reload_parity: 1920 тиков для четырёх оружий, пустой/непустой
  магазин, изменение duration, отмена: патроны/таймер/cue/drop/move совпали.
- shooting_3d_trigger_parity: 8100 тиков повторно, добавлено сравнение
  movement_multiplier при hip/ADS; расхождений нет.
- shooting_3d_magazine_smoke: четыре оружия, drop/скрытие/появление/отмена/F8;
  failures=0.
- shooting_3d_input_smoke, features_smoke, combat_smoke, menu_smoke прошли;

  Причина прежнего падения проверки скорости: теперь действует штатный

- Оконный кадр STG в фазе 0,50 просмотрен, магазин действительно отделён.
  Сохранён в 5_Проверки и отчёты/Полигон/core/polygon_3d_2026-11-12/STG_reload_50.png.

Численные контракты этих блоков подтверждены перечисленными сценариями.

строки аудита (хитбоксы, точный вид эффектов и прочие подсистемы).
