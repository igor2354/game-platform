# Внешний UBERgenerator

## Решение и границы — 13.11.2026

Пользователь поручил первую версию генератора из приложенного большого промпта,
отдельно от игры: `../UBERgenerator`. Редактор, проекты и инструменты не должны
увеличивать основной билд. Это отдельный Godot-проект с Start.cmd;
боевые системы, карты и меню основной игры не изменены.

Реализованы seed, простая 3D-земля/склоны, возвратный верхний тупик,
предпросмотр, выбор точек на схеме, числовая правка высоты, закрепление,
перегенерация незакреплённых точек, Undo/Redo, сохранение/чтение полного JSON v1,
проверка схемы, уклонов и подключения входа ветки. Входы веток сохраняются
при перегенерации. Новая полная генерация заменяет проект, но отменяется Undo.
При закрытии несохранённого проекта есть предупреждение.

`runner.gd` остаётся снаружи игры и запускается Godot с `--path game-platform`.
Загружает действующие `player_3d.gd`, его настройки и нативный визуал Genesis9;
физика/контроллер не копируются. Глубина черновых поверхностей ±1,1 м,
персонаж использует своё штатное ограничение Z. Проба подключает движение и
визуал, не весь Полигон с оружием, ИИ, освещением и прочими системами.
Это ограничение первого инструмента, не новая отдельная версия игровых механик.
Лестницы и прыжковые задачи пока не генерируются. Для подключения в готовый
EXE потребуется отдельный минимальный загрузчик; сейчас нужен соседний исходник.

Параметры берутся из инициализированного реального персонажа. Личный movement
CFG читается без записи, при отсутствии используются defaults и выводится
предупреждение. Остальные CFG не загружаются/не пишутся. Нового интерфейса
импорта общих игровых настроек нет. JSON ограничен 1 МБ, ресурсные пути/скрипты
из него не загружаются. Уровни сохраняют полную геометрию, версии, закрепления
и профиль: одного seed для восстановления не требуется.

## Стоимость и ограничения

Генерация 4–24 секции по 6 м плюс два крайних участка, импорт не более 128 точек
на маршрут / 8 ответвлений. Меш и выпуклая форма на сегмент; два переиспользуемых
материала. Полная перестройка только по изменениям, статичный SubViewport
обновляется один раз; редактор в покое использует low_processor_usage_mode.
Это небольшой ограниченный прототип, не реализация стриминга/локального кеша.
Длительная производительность не измерялась. Качество игры ради скорости
не снижалось; исходные игровые системы не изменены.

## Проверки 13.11.2026

Windows Godot 4.7.2: `../UBERgenerator/tests.gd` — 100 seed (детерминизм,
отдельная ветка), JSON с допуском чисел 0,00001 м, ошибки координат/версий,
редактирование, Undo/Redo, закрепление при перегенерации; failures=0.
Реальная физика player_3d, удержание действия вправо: seed 0 / 36 м без ветки,
seed 13011 / 72 м с веткой, seed 99 / 132 м с перепадом до 1,2 м и веткой —
выход достигнут, Z не отклонилась. Средний маршрут также пройден с окном;
просмотрены кадры редактора и игрового персонажа на склоне.
Это не полная симуляция баланса, художественная приёмка или проверка всех карт.
Личный movement CFG в окружении не найден; эти прогоны использовали defaults.

Снимки созданы через путь `tools/media_paths.gd`:
[редактор](../../../../5_Проверки%20и%20отчёты/Полигон/core/ubergenerator_2026-11-13/editor.png),
[проба](../../../../5_Проверки%20и%20отчёты/Полигон/core/ubergenerator_2026-11-13/playtest.png).
Журналы — снаружи в UBERgenerator (`tests.log`, `flat_smoke.log`, `hills_smoke.log`,
`window_play.log`). Сообщения root certificate store / недоступного user shader
cache являются ограничениями окружения; отдельно проверять SCRIPT ERROR/FAIL.

Следующий этап предлагается, но ещё не поручен: свободные узлы маршрута,
локальная перегенерация выделения и проверка объёма свободного прохода.
Модели, тематический арт, EditorPlugin и редактор внутри игры ещё не реализованы.
