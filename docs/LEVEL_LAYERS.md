# Порядок слоёв и обоснованные перекрытия

Указание пользователя и сверка кода **2026-10-31**.

Общий порядок: **небо → дальние планы → задние стены/декор → игровой план
и акторы → явно назначенные ближние перекрытия → эффекты/диагностика → HUD**.
Порядок создания узлов сам по себе не является обоснованием скрывать врага.

| Категория | Правило |
|---|---|
| Небо/дальние планы | Всегда позади текущей игровой плоскости |
| Задняя стена, маркер перехода | Не перекрывают героя и врагов, идущих перед ними |
| Игровой план | Поверхности и объекты согласованы с коллизиями и читаемостью акторов |
| Ближний декор | Перекрытие разрешено только конкретному предмету в конкретном месте с понятной пространственной причиной |
| Освещение/туман | Отдельные функциональные слои; их затемнение не оправдывает непрозрачную дверь поверх врага |
| HUD/меню | Над миром, с независимыми слоями интерфейса |

Список будущих объектов/мест перекрытия пользователь уточнит позже.

**Проектируемый слой «терраформинг», 2026-11-02:** внутренний материал
располагается под разрушаемой поверхностью; маска открывает его по фактическому
контуру удаления. Согласованно скрывать только относящиеся к разрушению
части игрового плана и ближних перекрытий. Акторов и независимые фоны маска
не вырезает. В пустоте кратера не создавать ложную сплошную опору; пролом
перекрытия открывает нижний этаж. Это план, порядок текущих сцен не менялся.
[Устройство и ограничения](CORE_TERRAFORMING.md#4-изображение-слой-терраформинг).

Не назначать весь декор передним планом и не поднимать всех акторов поверх
всех построек: это уничтожит осмысленные укрытия и пространственные отношения.

Фактический дефект полигона: переходные двери создавались после врагов
с тем же z=0 и перекрывали их. `CoreTransitionDoor` теперь задаёт z=-2:
это маркер на заднем плане, не физическая створка в плоскости движения.
Проверены z-порядок и оконный кадр врага перед дверью. На обычные будущие
открывающиеся двери правило автоматически не переносится без их конструкции.

Текущие значения относительны родителям: акторы обычно z=0; дверь z=-2;
план пролога находится на итоговом z=0 и создаётся раньше акторов, ближняя
группа пролога 1 — итоговый z=3. Освещение помещения использует z=20/22,
туман — z=100. CanvasLayer интерфейса не сравнивается напрямую с этими z.
При новой вложенности учитывать итоговый порядок, не только локальное число.
